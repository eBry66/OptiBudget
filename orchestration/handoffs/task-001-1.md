## Deviation from a strict five-commit split

`scripts/check-coverage.mjs`'s default scan walks all of `tests/`. Once the
fixture tests for check-coverage existed under `tests/fixtures/check-coverage/`
— using filenames that deliberately match the `AC-0NN.<slug>.test.ts`
naming contract, because that's what they're testing — the real, default
run of `check-coverage.mjs` in CI would have scanned them too and either
(a) wrongly counted a fixture file as covering a real AC id, or (b) failed
CI over a title-prefix mismatch in a fixture that isn't a real AC at all.

I only discovered this once the fixtures existed (commit 5), by which point
`check-coverage.mjs` was already committed (commit 3). Amending or
rebasing commit 3 was not available without an interactive rebase, which
AGENTS.md rules out. Rather than add a sixth commit outside your
instruction, I folded a small fix — skip any directory literally named
`fixtures` during the scan — into commit 5, and said so plainly in that
commit's message. Flagging it here too in case that call should have gone
the other way.

## Implementation decisions made where task-001.yml left the field open

task-001.yml's own notes say path normalization, unknown-key handling, and
diff-range semantics are the scripts' own implementation decisions,
reviewed when drafted. Decisions made:

- **validate-state.mjs**: only the block list-form of `allowed_paths` /
  `required_checks` (key on its own line, `- item` beneath it) is
  recognized as a list — matching the literal shape in HITL_GUIDE.md
  §4.12's example. An inline `key: [a, b]` form would not be caught by the
  non-empty-list check. No other document in this repo uses that form.
- **validate-task.mjs**: base ref for the diff defaults to
  `origin/$GITHUB_BASE_REF` when running in CI (set automatically on
  `pull_request` events), else `--base <ref>` if given, else `main`. Diff
  is `git diff --name-only <base>...HEAD` (merge-base diff, standard for
  PR-style comparisons).
- **validate-task.mjs's id/branch/attempt equality check**: originally
  omitted (the deliverable's description named only two checks —
  allowed_paths subset and diff-touches-allowed_paths — and I followed
  that literally rather than inferring a third from header comments
  elsewhere in the same file). Confirmed as a real gap and added in
  commit 6; see "Resolved open question" above.
- **check-coverage.mjs** enforces both halves of the naming contract in
  engineering/TESTING.md: file existence (`tests/<area>/AC-0NN.<slug>.test.ts`)
  *and* that the matched file's content contains a test title prefixed
  `[AC-0NN]`. TESTING.md's "Coverage" section, read narrowly, only commits
  check-coverage.mjs to the file-existence half; I read the deliverable
  description's explicit mention of "test title prefixed [AC-0NN]" as
  meaning both halves are its job. Worth confirming.
